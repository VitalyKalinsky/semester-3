## 0. Как получить ассемблерный код? Что было сделано для его генерации?

### Способ 1: В среде Visual Studio через отладчик (GUI) — как получены `main.txt` и `main_ptr.txt`
1. Поставить точку останова (F9) на первой исполняемой строке `main()` (например, на `iMas[3] = 12;`).
2. Нажать **F5** (Запуск отладки).
3. Когда выполнение остановится, открыть окно дизассемблера: **Ctrl + Alt + D** (или меню: *Отладка $\to$ Окна $\to$ Дизассемблированный код*).
4. Кликнуть правой кнопкой мыши внутри окна и включить пункт **«Показать байты кода»** (*Show Code Bytes*), чтобы видеть машинные коды (опкоды).

### Способ 2: Через командную строку компилятором MSVC (`cl.exe`)
Выполнить команду:
```powershell
cl.exe /c /Od /FAcs main.cpp
```
* `/c` — только компиляция без линковщика;
* `/Od` — отключение оптимизации (режим Debug);
* `/FAcs` — генерация листинга `.cod` с исходным кодом C++, ассемблером и байтами машинного кода.

> **О разрядности (x86 vs x64):**
> По умолчанию проект Visual Studio компилируется в режиме **x64**. В этом режиме используются 64-битные регистры (`rax`, `rcx`, `rdx`, `rbp`, `rsp`) и 64-битные указатели (`qword ptr` = 8 байт). При этом переменные типа `int` и `unsigned int` имеют размер 4 байта и обрабатываются командами с `dword ptr`. Ниже приведён разбор именно этого фактического кода из ваших файлов `main.txt` и `main_ptr.txt`.

### Шаги 1--4. Замена циклического фрагмента, трансляция и сопоставление Си и ассемблера

В программе-шаблоне циклический фрагмент заменён на код варианта 2-8:
```cpp
for (i = 0; i < 9; i++) {
    if (i >= 4)
        iMas[i] = 13 * i + 7;
    else
        iMas[i] = (i * 8) ^ 0xC;
}
```

Ниже показано, как компилятор транслировал каждую инструкцию Си в машинные команды:

1. **`iMas[3] = 12;`**
   ```asm
   mov    eax, 4           ; Загрузка размера int (4 байта)
   imul   rax, rax, 3      ; Вычисление смещения: 3 * 4 = 12 (0x0C) байт
   lea    rcx, [iMas]      ; Получение базового адреса массива iMas (07FF630CDC240h)
   mov    dword ptr [rcx+rax], 0Ch ; Базово-индексная запись константы 12
   ```
2. **`iMas[4] = 12345;`**
   ```asm
   mov    eax, 4
   imul   rax, rax, 4      ; Смещение: 4 * 4 = 16 (0x10) байт
   lea    rcx, [iMas]
   mov    dword ptr [rcx+rax], 3039h ; Запись 12345 (0x3039)
   ```
3. **`iMas[5] = 12345678;`**
   ```asm
   mov    eax, 4
   imul   rax, rax, 5      ; Смещение: 5 * 4 = 20 (0x14) байт
   lea    rcx, [iMas]
   mov    dword ptr [rcx+rax], 0BC614Eh ; Запись 12345678 (0x00BC614E)
   ```
4. **`iMas[6] = 0x123456789ABCDE;`**
   ```asm
   mov    eax, 4
   imul   rax, rax, 6      ; Смещение: 6 * 4 = 24 (0x18) байта
   lea    rcx, [iMas]
   mov    dword ptr [rcx+rax], 789ABCDEh ; Усечение: запись младших 32 бит
   ```
5. **`pI = &iMas[2]; *pI = 0xAB12;`**
   ```asm
   mov    eax, 4
   imul   rax, rax, 2      ; 2 * 4 = 8 байт
   lea    rcx, [iMas]
   add    rcx, rax         ; rcx = адрес элемента iMas[2]
   mov    rax, rcx
   mov    qword ptr [pI], rax ; Запись 8-байтового адреса в указатель pI
   mov    rax, qword ptr [pI] ; Чтение адреса из pI в rax
   mov    dword ptr [rax], 0AB12h ; Косвенная запись константы 0xAB12 по адресу в rax
   ```
6. **`for (i = 0; i < 9; i++)` (Инициализация и проверка):**
   ```asm
   mov    dword ptr [i], 0 ; i = 0
   jmp    main+0BCh        ; Прыжок на проверку условия
   ```
7. **Шаг цикла `i++`:**
   ```asm
   main+0CEh:
   mov    eax, dword ptr [i] ; Загрузка i
   inc    eax                ; i + 1
   mov    dword ptr [i], eax ; Сохранение обновленного i
   ```
8. **Проверка условия `i < 9`:**
   ```asm
   main+0BCh:
   cmp    dword ptr [i], 9   ; Сравнение i с 9
   jae    main+108h          ; Если i >= 9, выход из цикла
   ```
9. **`if (i >= 4)`:**
   ```asm
   cmp    dword ptr [i], 4   ; Сравнение i с 4
   jb     main+0EAh          ; Если i < 4, переход в else (беззнаковый переход)
   ```
10. **Ветка `then` (`iMas[i] = 13 * i + 7;`):**
    ```asm
    imul   eax, dword ptr [i], 0Dh ; eax = i * 13 (0x0D)
    add    eax, 7                  ; eax = 13 * i + 7
    mov    ecx, dword ptr [i]      ; ecx = i
    lea    rdx, [iMas]             ; rdx = адрес массива
    mov    dword ptr [rdx+rcx*4], eax ; Запись в массив: База + Индекс * 4
    jmp    main+106h               ; Обход ветки else
    ```
11. **Ветка `else` (`iMas[i] = (i * 8) ^ 0xC;`):**
    ```asm
    main+0EAh:
    mov    eax, dword ptr [i]      ; Загрузка i в eax
    shl    eax, 3                  ; i * 8 через побитовый сдвиг влево на 3
    xor    eax, 0Ch                ; Побитовое исключающее ИЛИ с константой 12
    mov    ecx, dword ptr [i]      ; ecx = i
    lea    rdx, [iMas]             ; rdx = адрес массива
    mov    dword ptr [rdx+rcx*4], eax ; Запись в массив: База + Индекс * 4
    ```

### Шаг 5. Список переменных и карта памяти

В нашей программе переменные объявлены **глобально** (вне функций). Они размещаются в статической памяти данных по фиксированным адресам:

| Переменная | Класс памяти | Тип | Размер | Диапазон адресов в памяти |
| :--- | :---: | :---: | :---: | :--- |
| `iMas[0..9]` | глобальная | `int[10]` | 40 байт ($28_{16}$) | `0x07FF630CDC240` -- `0x07FF630CDC267` |
| `pI` | глобальная | `int*` | 8 байт ($8_{16}$) | `0x07FF630CDC268` -- `0x07FF630CDC26F` |
| `i` | глобальная | `unsigned int` | 4 байта ($4_{16}$) | `0x07FF630CDC270` -- `0x07FF630CDC273` |

* **Локальные переменные:** если объявить переменные внутри `main()`, память выделяется в стеке текущего кадра, а доступ осуществляется по базово-смещённой адресации относительно регистра `rbp`: `[rbp - offset]`.
* **Локальные static:** размещаются аналогично глобальным переменным в статической секции данных по постоянным адресам, но область их видимости ограничена функцией.

### Шаг 8. Многокомпонентная адресация данных

Многокомпонентная адресация использована в командах записи в массив:
```asm
mov dword ptr [rdx+rcx*4], eax   ; Машинный код: 89 04 8A
```
Компоненты исполнительного адреса:
* **База (Base):** регистр `rdx` — хранит начальный адрес массива `iMas` (`0x07FF630CDC240`);
* **Индекс (Index):** регистр `rcx` — хранит номер текущего элемента $i$ ($0, 1, \dots, 8$);
* **Масштаб (Scale):** множитель 4 — соответствует размеру типа `int` (4 байта);
* **Смещение (Displacement):** равно 0.

Аппаратная формула адреса: $\text{Исполнительный адрес} = rdx + rcx \cdot 4$.

---

### Шаг 9. Адресация в командах перехода

Во всех командах ветвления использована **относительная адресация (`rel8`)**:
* `jmp main+0BCh` (код `EB 0E`): переход на проверку условия со смещением `+0x0E`.
* `jae main+108h` (код `73 43`): беззнаковый переход выхода из цикла при $i \ge 9$ со смещением `+0x43`.
* `jb main+0EAh` (код `72 1C`): беззнаковый переход в ветку `else` при $i < 4$ (по флагу переноса $CF = 1$) со смещением `+0x1C`.
* `jmp main+106h` (код `EB 1C`): безусловный обход ветки `else`.
* `jmp main+0AEh` (код `EB A6`): переход на шаг цикла `i++` с отрицательным смещением `0xA6` ($-90$ в дополнительном коде).

### Шаг 10. Доступ через указатель и сравнение способов адресации

В файле `main_ptr.cpp` доступ к элементам массива реализован через указатель:
```cpp
int *pMas = iMas;
for (i = 0; i < 9; i++, pMas++) {
    if (i >= 4)
        *pMas = 13 * i + 7;
    else
        *pMas = (i * 8) ^ 0xC;
}
```

Дизассемблер показал:
```asm
; Шаг цикла pMas++:
mov  rax, qword ptr [pMas]
add  rax, 4                  ; Простое прибавление 4 байт к адресу!
mov  qword ptr [pMas], rax

; Запись в массив (*pMas = ...):
mov  rcx, qword ptr [pMas]
mov  dword ptr [rcx], eax    ; Косвенно-регистровая адресация [rcx] (код 89 01)!
```

**Сравнение способов адресации:**
1. **Индекс против указателя:** При доступе по индексу процессор на каждом шаге цикла вынужден вычислять формулу `rdx + rcx*4`, используя команду с SIB-байтом (`89 04 8A`). При доступе через указатель адрес увеличивается простым сложением `add rax, 4`, а запись превращается в простую 2-байтовую команду косвенно-регистровой адресации `mov [rcx], eax` (`89 01`).
2. **Глобальные переменные против локальных:** Глобальные переменные имеют постоянные адреса в секции данных (прямая адресация). Локальные переменные создаются в стеке и адресуются со смещением относительно регистра кадра: `[rbp - offset]`.

## 2. Ответы на контрольные вопросы (1--10)

1. **Какие разновидности процессорных команд использованы для арифметических действий и почему?**
   * `imul` — умножение со знаком на 13.
   * `add` и `inc` — сложение и инкремент.
   * `shl` — умножение на 8 заменено побитовым сдвигом влево на 3 бита ($2^3 = 8$), так как сдвиг выполняется за 1 такт и экономит ресурсы АЛУ.
   * `xor` — побитовое исключающее ИЛИ с константой 12, а также быстрое обнуление `xor eax, eax` (`return 0`).
2. **Где находятся операнды-источники и операнды-приемники?**
   В синтаксисе Intel первый операнд — всегда приёмник, второй — источник: `mov [i], 0` (приёмник — память, источник — константа).
3. **Какие регистры процессора использованы и почему одни операнды в регистрах, а другие в памяти?**
   Использованы `rax`/`eax` (аккумулятор), `rcx` (индекс/адрес), `rdx` (база массива), `rbp` (база кадра), `rsp` (стек). Регистры работают мгновенно (0--1 такт), но их количество ограничено, поэтому переменные хранятся в памяти, а в регистры загружаются только на время расчётов.
4. **Как учитываются размеры и типы операндов?**
   Для 4-байтовых `int` и `unsigned int` используются 32-битные регистры (`eax`, `ecx`) и спецификатор `dword ptr`. Для указателей используются 64-битные регистры (`rax`, `rcx`, `rdx`) и `qword ptr`.
5. **Как компилятор организовал согласование размеров операндов (приведение типов)?**
   При записи 64-битной константы `0x123456789ABCDE` в 32-битный массив выполнено усечение: записаны только младшие 4 байта `0x789ABCDE`.
6. **Схема определения адреса операнда в памяти:**
   $\text{Адрес} = \text{База} + \text{Индекс} \times \text{Масштаб} + \text{Смещение}$. В `mov [rdx+rcx*4], eax` задействованы база, индекс и масштаб 4. Через указатель формула упрощается до косвенно-регистровой: `[rcx]`.
7. **Адресация в командах перехода:**
   Относительная адресация: адрес перехода равен $\text{IP} + \text{смещение}$. Для $i \ge 4$ сгенерирован беззнаковый переход `jb` (по флагу переноса $CF = 1$), так как `i` имеет тип `unsigned int`.
8. **Побитовый разбор двоичного кода команд:**
   * `89 04 8A` (`mov [rdx+rcx*4], eax`): Opcode `89` (`MOV r/m32, r32`); ModR/M `04` (`mod=00`, `reg=000`, `r/m=100` $\to$ есть SIB); SIB `8A` (`scale=10` $\to$ масштаб 4, `index=001` $\to$ `rcx`, `base=010` $\to$ `rdx`).
   * `89 01` (`mov [rcx], eax`): Opcode `89`; ModR/M `01` (`mod=00`, `reg=000`, `r/m=001` $\to$ `rcx`). Байт SIB отсутствует.
9. **Типовые последовательности команд языка Си:**
   * Присваивание константы: `mov dword ptr [addr], const`;
   * Обращение через указатель: `mov rax, [pI]; mov dword ptr [rax], val`;
   * Циклическая конструкция: `mov i, 0` $\to$ `jmp check` $\to$ `тело` $\to$ `inc i` $\to$ `check: cmp i, 9; jb тело`;
   * Условный оператор: `cmp i, 4; jb else_lbl; then_lbl: ...; jmp end_lbl; else_lbl:`;
   * Обращение к элементу массива по индексу: `mov [rdx+rcx*4], eax`.



## 3. Рассмотрим каждую ассемблерную команду подробно (процессор x86)

В соответствии с требованиями и структурой методических указаний ниже разобран побайтовый и побитовый состав 10 ключевых команд программы (соответствующих Таблице 3 отчёта).

### Общий формат команды процессора x86:
| Префиксы (0-4 байта) | Код операции (Opcode, 1-3 байта) | ModR/M (1 байт) | SIB (1 байт) | Смещение (Displacement, 1-4 байта) | Непосредственный операнд (Immediate, 1-4 байта) |
| :---: | :---: | :---: | :---: | :---: | :---: |

---

### Команда 1: `00007FF630CD1720  40 55  push rbp`
* **Машинные байты:** `40 55`
* **Побитовое представление:**
  * Байт 1 (`40h`): `0100 0000` — Префикс REX (`0100` — сигнатура REX, биты W=0, R=0, X=0, B=0).
  * Байт 2 (`55h`): `0101 0101` — Код операции `Opcode` (`01010` — операция `push`, `101` — регистр `rbp` / `ebp`).
* **Разбор полей:**
  * `5xh` — код операции PUSH в стек.
  * `x5h` — регистр `rbp` (в 32-битном x86: `ebp`).
* **Способ адресации:** **Неявная адресация** (операнд-приёмник вершина стека `[rsp]` адресуется неявно через аппаратный указатель стека).

---

### Команда 2: `00007FF630CD1723  48 81 EC E8 00 00 00  sub rsp, 0E8h`
* **Машинные байты:** `48 81 EC E8 00 00 00` (7 байт)
* **Побитовое представление:**
  * Байт 1 (`48h`): `0100 1000` — REX.W префикс (`W=1` задает 64-битный размер операнда `rsp`).
  * Байт 2 (`81h`): `1000 0001` — `Opcode` (`SUB r/m64, imm32`).
  * Байт 3 (`ECh`): `1110 1100` — `mod-reg-r/m`:
    * `MOD = 11` (3) — операнд в регистре.
    * `REG = 101` (5) — расширение кода операции (`/5` для `SUB`).
    * `R/M = 100` (4) — регистр `rsp` (в 32-битном x86: `esp`).
  * Байты 4..7 (`E8 00 00 00`): `Immediate` — константа `0x000000E8` (232 байта в Little-Endian).
* **Разбор полей:**
  * `81 /5 id` — `SUB r/m64, imm32` (вычитание 32-битного непосредственного значения с расширением знака).
  * `MOD = 3` — регистровая адресация (R/M содержит номер регистра).
  * `REG = 5` — код операции SUB.
  * `R/M = 4` — регистр `rsp` (`esp`).
  * `Immediate = 000000E8h` (размер выделяемой области стека).
* **Способ адресации:** **Непосредственная адресация** (источник — непосредственная константа).

---

### Команда 3: `00007FF630CD173C  B8 04 00 00 00  mov eax, 4`
* **Машинные байты:** `B8 04 00 00 00` (5 байт)
* **Побитовое представление:**
  * Байт 1 (`B8h`): `1011 1000` — `Opcode` (`B8 + rd` — `MOV r32, imm32`). Младшие 3 бита `000` соответствуют регистру `eax`.
  * Байты 2..5 (`04 00 00 00`): `Immediate` — 32-битная константа `4` (размер `sizeof(int)`).
* **Разбор полей:**
  * `B8+rd id` — `MOV r32, imm32`.
  * `+rd = 0` — регистр `eax`.
  * `Immediate = 00000004h`.
